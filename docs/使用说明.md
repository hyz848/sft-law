# 使用说明

从一台什么都没装好的电脑，到手里有一组能复现的数字。本文按操作顺序写，照着往下走即可。

- 项目是什么、目录里有什么 → `README.md`
- 参数表、超参、评测算法 → `finetune-qwen-law-sft.md`
- **具体怎么一步步做 → 本文**

---

## 0. 先看清全貌

这个项目分三段，**只有第一段能在你自己的电脑上跑**：

```
① 造数据（本机 CPU，几分钟）      ② 训练（平台 GPU，约 1 小时）      ③ 评测（GPU，10~30 分钟）
   原始 jsonl → 22,922 条分类数据     数据 → LoRA 适配器（约 40MB）      基线 vs 微调后 → 一组数字
```

为什么后两段必须上 GPU：分类任务要跑模型前向，评测时每条样本要算 50 个候选的概率，2,292 条就是 11 万次前向。CPU 上一步几十秒，跑完是天数的事；24G 卡上是分钟级。

**你要准备的东西**：一个手机号（注册平台用）、能上网、约 10 元（AutoDL 路线）或 0 元（魔搭路线）。

> **模型名只有一个正确答案**：`Qwen/Qwen3-1.7B`。Qwen3 的发布约定是「会后训练」的版本就叫 `Qwen3-1.7B`，基座版才叫 `Qwen3-1.7B-Base`；`Qwen3-1.7B-Instruct` 这个 ID 在魔搭和 HuggingFace 上都**不存在**，照抄会在拉模型那步 404。训练、评测、适配器全部统一用它。

## 2. 第一步：造数据（本机，几分钟）

### 2.1 一条命令出三份文件

```bash
python scripts/build_cls_dataset.py
```

它做的事：从 Triplet 里剥出问题、抽出部法名当标签、剔掉评测集问题、按 80/10/10 分层切分。

产物：

```text
data/cls/
├── train.jsonl      18,338 条
├── val.jsonl         2,292 条
├── test.jsonl        2,292 条
└── label_stats.json  50 类 + 每类条数 + 切分统计
```

### 2.2 跑完必须验这三句

不验就往下走，后面出错会以为是训练的问题。

```bash
# ① 类别数、总条数、切分数
python -c "import json;d=json.load(open('data/cls/label_stats.json',encoding='utf-8'));print(d['num_labels'],d['total'],d['splits'])"
# 期望：50 22922 {'train': 18338, 'val': 2292, 'test': 2292}

# ② 有没有空类（最小/最大应分别是 93 和 3727）
python -c "import json;d=json.load(open('data/cls/label_stats.json',encoding='utf-8'));print(min(d['labels'].values()),max(d['labels'].values()))"
# 期望：93 3727

# ③ 三份文件的问题零重叠
python -c "
import json
s=[{json.loads(l)['query'] for l in open(f'data/cls/{n}.jsonl',encoding='utf-8')} for n in ('train','val','test')]
print(len(s[0]&s[1]),len(s[0]&s[2]),len(s[1]&s[2]))"
# 期望：0 0 0
```

三句都对上，数据才算合格。有一个不对，先修数据，别急着训。

### 2.3 导出两个平台各自吃的格式

```bash
python scripts/export_platform_data.py
```

## 3. 第二步之一：魔搭路线（免费，适合第一次跑通）

### 3.1 领免费算力（约 10 分钟）

1. 打开 `modelscope.cn`，右上角注册，手机号收验证码登录。
2. 头像 → 账号设置 → **绑定阿里云账号**。授权页把权限**全勾上**，漏勾会导致创建实例失败。
3. 看到「已绑定」并显示剩余免费时长，就算成。
4. 我的 Notebook → 创建 → GPU 规格选 **A10 / 24GB**，镜像选 PyTorch 2.x + CUDA。

额度规则：按 GPU 小时扣，**单次运行上限约 10 小时，空闲 1 小时自动关机**。够训完一轮。

### 3.2 把数据传上去

持久化盘是 `/mnt/workspace`，关机不丢。在 Notebook 里建目录传文件：

```bash
mkdir -p /mnt/workspace/cls
# 用 JupyterLab 左侧文件树拖拽上传，或在本机打包后上传再解压
```

传的两个文件：`ms_swift/train.jsonl` 和 `ms_swift/val.jsonl`（加评测用的 `test_eval.jsonl`）。

传完先验一眼：

```bash
wc -l /mnt/workspace/cls/*.jsonl
head -n 1 /mnt/workspace/cls/train.jsonl
```

行数对不上就是没传完，别往下走。

### 3.3 装框架并起训

```bash
pip install ms-swift -U

swift sft \
  --model Qwen/Qwen3-1.7B-Instruct \
  --tuner_type lora \
  --quant_method bnb --quant_bits 4 \
  --dataset /mnt/workspace/cls/train.jsonl \
  --val_dataset /mnt/workspace/cls/val.jsonl \
  --torch_dtype bfloat16 \
  --num_train_epochs 2 \
  --per_device_train_batch_size 8 \
  --gradient_accumulation_steps 2 \
  --learning_rate 2e-4 \
  --lora_rank 16 --lora_alpha 32 \
  --target_modules all-linear \
  --max_length 512 \
  --eval_steps 100 --save_steps 100 --save_total_limit 2 \
  --logging_steps 20 \
  --warmup_ratio 0.05 \
  --output_dir /mnt/workspace/output/cls_qwen3
```

关键一句：**ms-swift 没有 `qlora` 这个 tuner**。QLoRA = `--tuner_type lora` + `--quant_method bnb --quant_bits 4`，两句一起才叫 QLoRA。

### 3.4 盯两个数

起训后先看这个：

```text
trainable params: ~20 M || all params: ~1.7 B || trainable%: ~1.2
```

`trainable%` 在 1%~2% 之间，说明只训了补丁，基数没动——这是对的。

再看 loss 和 eval：

```bash
tail -f /mnt/workspace/output/cls_qwen3/*/logging.jsonl
```

盯 `eval_accuracy` 的走向：涨到不涨了就可以停。你的数会和课时页不同，形态对就行。

### 3.5 把适配器拿回来

```bash
# 先找 eval_accuracy 最高的那个 checkpoint，别拿最后一个
grep -h "eval_accuracy" /mnt/workspace/output/cls_qwen3/*/logging.jsonl | tail -20

cd /mnt/workspace/output/cls_qwen3
tar -czf cls_adapter.tar.gz v0-*/checkpoint-800/
```

然后在 JupyterLab 文件树里右键下载这个 tar（约 40MB）。**别整包下载**，checkpoint 有好几个，加起来几百兆。

## 4. 第二步之二：AutoDL 路线（按小时付费，适合反复跑）

### 4.1 租卡（约 8 分钟）

1. `autodl.com` 手机号注册，进控制台。
2. 右上角充值，**10 元起**（够跑两三节课）。
3. 算力市场 → 地区随便 → GPU 选 **RTX 4090 / 24GB**（约 2 元/小时上下，以官网实时价为准）。
4. 点 1 张 → 选镜像 → 创建。状态变「运行中」，右侧出现 JupyterLab。

计费只看「开没开机」，不看有没有在跑任务。**跑完立刻关机**——挂一晚上就是十几块。

### 4.2 选镜像

镜像一栏选**社区镜像**，搜 `LLaMA-Factory`，挑更新日期近的。这省掉整套环境安装，是 AutoDL 相对魔搭最大的省事点。

开机后进 JupyterLab，先确认框架在：

```bash
llamafactory-cli version
# 期望：LLaMA-Factory, version 0.9.x
```

打不出来就换镜像，别在旧版本上迁就参数。

定位代码目录（**别硬猜**）：

```bash
find / -maxdepth 3 -name "LLaMA-Factory" -type d 2>/dev/null
```

多数镜像放在 `/root/LLaMA-Factory`。

### 4.3 传数据并注册

```bash
# 数据盘：/root/autodl-tmp（关机不丢）
cp cls_train.jsonl cls_val.jsonl /root/autodl-tmp/LLaMA-Factory/data/
```

然后在同目录的 `dataset_info.json` 里加两段：

```json
"cls_law": {
  "file_name": "cls_train.jsonl",
  "columns": { "prompt": "instruction", "response": "output" }
},
"cls_law_val": {
  "file_name": "cls_val.jsonl",
  "columns": { "prompt": "instruction", "response": "output" }
}
```

`columns` 在说「我文件里 `instruction` 这个字段，就是你要的 prompt」。字段名和默认一致时可以不写，但写上更保险。

验一眼注册生效了：

```bash
wc -l /root/autodl-tmp/LLaMA-Factory/data/cls_*.jsonl
python -c "import json;d=json.load(open('/root/autodl-tmp/LLaMA-Factory/data/dataset_info.json'));print(list(d))"
# 列表里应出现 cls_law 和 cls_law_val
```

三个最容易错的地方：**文件必须放在 `data/` 目录下**（`file_name` 写相对路径）；**JSON 多一个逗号整个文件就废了**，训练会报 `dataset not found`；**改完没重启 notebook 进程，读的还是旧缓存**。

### 4.4 写 yaml 起训

在 `LLaMA-Factory` 目录下建 `cls_qlora.yaml`：

```yaml
### model
model_name_or_path: Qwen/Qwen3-1.7B-Instruct
trust_remote_code: true

### method
stage: sft
do_train: true
finetuning_type: lora
lora_rank: 16
lora_alpha: 32
lora_target: all

### dataset
dataset: cls_law
eval_dataset: cls_law_val
template: qwen3
cutoff_len: 512
preprocessing_num_workers: 8

### output
output_dir: /root/autodl-tmp/saves/qwen3-1.7b/cls
logging_steps: 20
save_steps: 200
eval_steps: 200
eval_strategy: steps
save_total_limit: 2
plot_loss: true

### train
per_device_train_batch_size: 8
gradient_accumulation_steps: 2
learning_rate: 2.0e-4
num_train_epochs: 2.0
lr_scheduler_type: cosine
warmup_ratio: 0.05
bf16: true

### QLoRA：两条一起才叫 QLoRA
quantization_bit: 4
quantization_method: bnb

### 加速
use_unsloth: true
```

起训：

```bash
cd /root/LLaMA-Factory
llamafactory-cli train cls_qlora.yaml
```

| 要调的东西 | ms-swift 写法 | LLaMA-Factory 写法 |
|---|---|---|
| 训练数据 | `--dataset` 路径.jsonl | `dataset:` 注册名 |
| 验证数据 | `--val_dataset` 路径.jsonl | `eval_dataset:` 注册名 |
| QLoRA | `--quant_bits 4` | `quantization_bit: 4` |
| 截断长度 | `--max_length 512` | `cutoff_len: 512` |
| 学几轮 | `--num_train_epochs 2` | `num_train_epochs: 2.0` |

参数一一对应，变的只是写法：一个在命令行，一个在文件里。看不懂 yaml 时，逐行翻回命令行就懂了。

**Unsloth 报错怎么办**：部分镜像的 Unsloth 与 4bit 量化打架。真撞上报 unsloth 相关错误，把 `use_unsloth: true` 那行注掉再跑——慢一点但能跑完。

### 4.5 拿 adapter

```bash
cd /root/autodl-tmp/saves/qwen3-1.7b/cls
ls                      # checkpoint-600/ checkpoint-800/ training_loss.png trainer_log.jsonl
tar -czf cls_adapter.tar.gz checkpoint-800/
```

`output_dir` 一定要写在 `/root/autodl-tmp/` 下。写在 `/root/` 里，关机可能随系统盘一起被释放，几小时白跑。

## 5. 第三步：评测

### 5.1 顺序不能反：先量基线

```bash
# 不加载适配器，量 zero-shot（先跑 200 条估个大概）
python scripts/eval_cls.py --no-adapter --limit 200
```

**这步要 GPU**：脚本会加载 1.7B 基座做前向，本机没卡跑不动（CPU 上一条几十秒，200 条就是一小时起）。所以评测放在平台机器上做，或者在有卡的机器上跑。

没有这个数，「微调后 88%」什么都说明不了。

### 5.2 再量微调后

```bash
# 在平台 GPU 上直接指适配器路径
python scripts/eval_cls.py --adapter /root/autodl-tmp/saves/qwen3-1.7b/cls/checkpoint-800
```

或者把适配器下回本机、在有 GPU 的机器上跑。**同一个 test 集、同一个 prompt、同一套打分**——三者有一个变了就不叫对照。

### 5.3 输出长这样

```text
==============================================
accuracy : 0.8734
macro-F1 : 0.7126
top-3    : 0.9541
----------------------------------------------
F1 最差的 5 类（含 test 条数）：
  公益事业捐赠法: F1=0.412  test=8 条
  ...
==============================================
报告已写入 eval_report.json
```

> **上面这组数是格式示意，不是本项目的实测值。** 分类线的 zero-shot 基线和微调后指标目前还是空的（要 GPU 跑才有），别把这组数当结论引用。你自己跑出来是多少就是多少。

同时会写一份 `eval_report.json`：

| 字段 | 内容 |
|---|---|
| `accuracy` / `macro_f1` / `top3` | 三个汇总指标 |
| `per_class` | 每个部法的 `test` 条数、`hit` 命中数、`f1` |
| `confusion` | 50×50 混淆矩阵，行是真实、列是预测 |
| `model` / `adapter` / `mode` / `n` | 基座、适配器路径、模式（zero-shot / finetuned）、评测条数 |

**为什么报「F1 最差的 5 类」还带条数**：公益事业捐赠法 test 只有 8 条，错 1 条就是 12.5 个百分点。只报百分比等于没报，必须带分母。

### 5.4 结果怎么读

| 指标 | 看什么 | 正常范围 |
|---|---|---|
| accuracy | 整体对了多少 | 微调后应明显高于基线 |
| macro-F1 | 每类平均好不好 | 通常低于 accuracy（小类难） |
| top-3 | 差一点就对的有多少 | 接近 accuracy 说明模型有把握 |
| F1 最差 5 类 | 病灶在哪 | 重点看是不是那两个易混对 |

两个易混对是固定的：**民法典 / 民事诉讼法**、**刑法 / 刑事诉讼法**。名字像、内容近，模型最容易在这里翻车。混了不奇怪，指得出来就行。

### 5.5 两个平台对照（跑了才有）

| 指标 | 魔搭 | AutoDL | 怎么算合格 |
|---|---|---|---|
| accuracy | 自己填 | 自己填 | 两者差在 0.5 个点内 |
| macro-F1 | 自己填 | 自己填 | 差很多说明训练没收敛或数据不一致 |
| 用时 / 费用 | 约 1 小时 / 免费 | 约 1 小时 / 时长 × 单价 | 自己算一遍 |

两个平台训同一个任务、同一份数据，结果应当很接近。差出好几个点，先查数据和超参是否一致，别急着归因到平台。

## 6. 岔子速查

| 现象 | 真实原因 | 怎么办 |
|---|---|---|
| `dataset not found` | LLaMA-Factory 的 `dataset` 要填**注册名**，不是文件路径 | 在 `dataset_info.json` 里注册，yaml 写 `cls_law` |
| 注册了还是找不到 | 文件没放在 `data/` 下，或 JSON 多逗号 | 放对目录，`python -c "import json;json.load(open(...))"` 验一遍 |
| 准确率虚高，换真实数据就掉 | 评测集问题混进了训练集 | 重跑 `build_cls_dataset.py`，别加 `--keep-evalset` |
| 模型只会抄法条 | 输入里没剥掉法条原文 | 同上，用默认脚本重造数据 |
| 长名部法系统性判错 | 候选打分没按 token 数取平均 | 这是打分代码问题，不是模型问题 |
| 小类准确率忽高忽低 | test 条数太少 | 报数时带上分母 |
| 训练 OOM | batch 或 max_len 太大 | batch 降到 4、`cutoff_len` 降到 384 |
| Unsloth 报错 | 与 4bit 量化冲突 | 注掉 `use_unsloth` |
| 关机后模型没了 | `output_dir` 写在系统盘 | 一律写 `/root/autodl-tmp/` |
| 手测结果比评测差很多 | 聊天没带 `--template qwen3` | 模板不对，输入格式和训练时不一致 |
| 魔搭创建实例失败 | 授权没全勾 / 当前时段没资源 | 重绑账号全勾授权；换个时段或可用区 |

## 7. 时间与成本

| 阶段 | 耗时 | 花费 |
|---|---|---|
| 本机造数据 | 2~5 分钟 | 0 |
| 魔搭训练（A10 24G） | 约 1 小时 | 0（免费额度 36 小时，单次上限 10 小时） |
| AutoDL 训练（4090 24G） | 约 1 小时 | 约 2 元（1.88 元/时上下，以官网为准） |
| 评测（200 条估算） | 5~10 分钟 | 算在机器费里 |
| 评测（2,292 条全量） | 20~30 分钟 | 同上 |

显存账：基座 0.9G + LoRA 权重梯度 0.3G + 激活 2~4G + CUDA 上下文 1~2G ≈ **5~7G**。24G 卡占用不到三分之一，12G 卡（3060 / 4070）也能跑，8G 卡要把 batch 压到 2~4。

别在现场跑「全参 vs QLoRA」对照：全参 1.7B 要 20G 以上，24G 卡卡在 OOM 边缘，一崩就掉课堂节奏。全参只讲数字。

## 8. 做完的判据

手里应该有三样东西，缺一样都算没做完：

| 交付物 | 具体是什么 | 怎么验 |
|---|---|---|
| 数据 | `data/cls/` 三份 jsonl + `label_stats.json` | 50 类无空类、三份零重叠 |
| 模型 | LoRA 适配器（约 40MB）+ 训练日志 | `adapter_config.json` 在，`trainable%` 在 1%~2% |
| 尺子 | 基线 vs 微调后的对照表 + 混淆矩阵 | 别人拿你的数据能算出同样的数 |

最终判据只有一句：**换台机器、换个人，照这份说明能跑出同一个数**。差在 0.5 个点以内，这条链才算真通了。
